# N2 incremental evidence value trial (PP1)

**Purpose:** Investigate whether prior maintenance evidence H/M/F/R adds out-of-fold information about *realized individual squared prediction loss* beyond the machine's original predicted failure probability.

This is a secondary exploratory analysis of the existing 7-day, synthetic Azure PdM benchmark. The input is generated by `n2_continuous_analysis.py`; **do not use test outcome labels as predictors**. The script does not retrain the original failure classifier.

## Run from `research/component3` on Windows CMD

```cmd
python scripts\test_n2_risk_vs_evidence.py --input outputs_n2_continuous\n2_prediction_evidence_and_losses.csv
python scripts\n2_risk_vs_evidence.py --input outputs_n2_continuous\n2_prediction_evidence_and_losses.csv --out-dir outputs_n2_incremental
```

Already installed requirements from `requirements_n2.txt` are sufficient.

## Predeclared comparisons

- `constant_mean_loss`: out-of-fold overall mean loss (no predictors).
- `risk_only`: original model risk `p` and `p**2`, so the baseline can express nonlinear risk–loss relationships.
- `risk_plus_recency`: `p`, `p**2`, and days since most recent historical maintenance event (R).
- `risk_plus_HMF_machine`: `p`, `p**2`, observed history span (H), prior maintenance count (M), prior failure count (F), and machine type.
- `risk_plus_HMFR_machine`: all of the above including R.

All non-constant alternatives use the same fixed Ridge regression (`alpha=5`), preprocessing fitted within each fold, and identical five-fold **machine-grouped** out-of-fold predictions. Report MAE, RMSE and R²; don't imply an association is causal. Positive `delta_mae_risk_minus_full_evidence` favors adding evidence under this experiment.

The original N2 predictions were separately refitted for each of the full/180-day/90-day conditions. The experiment preserves each condition's own evidence and predictions.

## Critical limitations

1. Original failure classifiers saw earlier observations for these same 100 machines; GroupKFold only protects the *second-stage loss model* from same-machine overlap.
2. We already inspected the prediction test period, so this is not untouched final validation.
3. The outcome is **squared prediction error**, not a directly measured individual-machine reliability percentage.
4. Observed history span H is elapsed since earliest observed maintenance event, not verified log-collection coverage.
5. R measures recency of a maintenance event (machine state), not whether the database has stale or missing records. R strongly relates to failure prevalence in this synthetic dataset.
6. C is constant 100% in published fields and is intentionally excluded; simulated missingness should be explicitly labelled in future work.
7. Repeated snapshots and overlapping horizons are correlated; no independence-based statistical significance claims are made.
8. Comparing risk-only vs risk-plus-evidence is a stronger association/added-value check, but it does not prove that changing evidence *causes* better predictions. Independently validate with real factory maintenance histories when possible.
